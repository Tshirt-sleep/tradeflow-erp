# TradeFlow ERP 全栈升级路线与操作说明

## 目标和当前状态

项目已从前端演示版升级为 Vue 3 + Express + SQLite 的本地全栈应用，包含订单履约、库存预占、用户权限、数据库备份、阿里云部署准备。订单通过本地手工录入，发货时手动登记承运商和追踪号；当前没有云端部署。

## 实施顺序

### 阶段 1：订单与库存规则（已实现）

- 确认订单时在数据库事务内校验“现有库存 - 已预占库存”，按 SKU 汇总并预占；缺货订单不会进入待发货。
- 待处理和待发货订单可填写原因后取消。待发货订单取消时会释放预占。
- 发货时必须有匹配的预占记录；事务内扣减现有库存及预占量，阻止超卖和重复扣减。
- 已发货订单可标记为已完成；订单事件和库存变更流水可追溯。
- 库存页面显示现有量、预占量、可用量和最近变更流水。
- 管理员可通过库存调整弹窗登记入库、盘点差异或损耗；必须填写正负整数和原因，调整后现有库存不能低于订单预占量，流水记录操作人及原因。运营和只读角色不能手动调整库存。
- 新增商品时，初始库存也写入带操作人的期初库存流水，避免账面库存没有来源记录。
- 确认、拒绝/取消、发货和完成订单均记录操作账号、时间与适用的处理原因；订单详情提供操作历史。
- 旧待发货订单如果无法安全预占，会保持原状态、显示库存待处理并阻止发货，交由管理员处理。

### 阶段 2：用户与权限（基础能力已实现）

- 首次使用时由用户创建管理员；口令使用 scrypt 哈希，不保存明文，至少 12 位。
- 登录会话保存在 SQLite，随机令牌只存 SHA-256 摘要；HttpOnly、SameSite=Lax，12 小时到期。
- 管理员管理用户、角色和账户启停；运营可处理订单；只读账号只能查看。API 服务端负责授权。
- 登录失败有限流；阿里云 Caddy 拓扑通过 `TRUST_PROXY_HOPS=1` 使用真实客户端 IP，本地默认不信任代理；停用账户会撤销其会话。
- 生产首次初始化要求服务器设置至少 32 位的 `TRADEFLOW_SETUP_TOKEN`，初始化页面必须提交此口令；生产环境漏配时阻止创建首个账号，创建后初始化接口关闭。
- 新增用户、修改角色、停用或重新启用会写入用户权限审计记录，并由管理员在“用户与权限”页面查询。
- 订单状态和人工库存变更已记录操作者；用户角色/启停管理审计、密码重置/MFA 和更细的字段权限仍可继续完善。暂不支持账号找回。

### 阶段 3：云端部署与备份（部署包和备份能力已实现，云资源未部署）

- `Dockerfile` 和 `compose.yaml` 可将 Express、构建后的前端运行在同一个容器；SQLite 使用持久卷，默认只绑定服务器本机地址，应由 HTTPS 反向代理访问。
- 生产首次启动默认不灌入虚构的演示商品和订单，专用演示部署需显式设置 `TRADEFLOW_SEED_DEMO_DATA=true`；本地开发仍默认加载示例数据。
- `DATA_DIR` 可配置为云主机的持久化磁盘路径。首次启动自动创建一份备份，此后每 24 小时创建一份；本地保留最近 30 份。
- 管理员可从“备份管理”手动创建、下载和恢复 SQLite 快照。恢复前自动保留安全副本并校验数据库完整性；恢复后应用当前兼容迁移，再撤销现有会话。
- 可将新备份同步到阿里云 OSS 的 S3 兼容接口。ECS RAM 角色模式必须同时设置私有 Bucket、地域、S3 Endpoint 和备份前缀；本地静态凭据模式需配置完整 AccessKey。只有凭据配置完整时，界面才显示异地备份已启用；配置缺项会明确提示且本地快照仍可创建。远端保留周期由 Bucket 生命周期策略管理。也保留 AWS S3/R2 等兼容服务的配置能力。
- 阿里云 Terraform 为专用备份前缀创建 OSS 生命周期规则，默认 365 天过期，可通过 `backup_retention_days` 设置为 30 到 3650 天；本机保留最近 30 个快照。部署计划中应结合恢复目标和费用核对该天数。
- 阿里云 Terraform 为 ECS 系统盘和数据盘绑定自动快照策略，默认每日 03:00（UTC+8）运行并保留 7 天，可通过 `ecs_snapshot_retention_days` 设置为 1 到 365 天；该服务增加存储费用，创建前必须结合实际数据量审阅报价。
- 若 OSS 上传失败，本地快照继续保留并显示待同步状态；后台每 30 分钟自动补传，管理员也可手动重试。快照与补传串行执行，恢复流程先等待正在执行的备份任务完成。
- 云平台已选择阿里云；账号授权、地域、域名、ECS、HTTPS 反向代理、OSS Bucket 和凭据尚未提供，因此目前没有创建云资源或上传业务数据。
- 部署前还需要配置云主机持久盘、TLS、最小权限的 RAM 角色、日志监控，并完成恢复演练。阿里云的完整 ECS/OSS 步骤见[阿里云部署与备份](阿里云部署与备份.md)。多人并发或数据规模增长后，再将 SQLite 迁移至托管 PostgreSQL。

## 数据模型

- `products`：SKU、名称、USD 售价（整数美分）、现有库存、预占库存、阈值、在售状态。
- `orders` / `order_items`：订单状态及总额、商品下单快照、取消/发货信息。
- `order_inventory`：订单商品预占、释放、消耗状态。
- `inventory_ledger`：库存现有量/预占量变化前后的记录，人工调整额外记录操作者及原因。
- `order_events`：订单状态事件、取消原因、操作者与时间。
- `users` / `auth_sessions`：角色、口令哈希、会话令牌摘要与过期时间。
## API 摘要

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 服务、数据库、持久化目录写入状态和远端备份是否配置；存储或数据库不可用返回 503 |
| GET/POST | `/api/auth/setup-status`、`/api/auth/setup`、`/api/auth/login`、`/api/auth/me`、`/api/auth/logout` | 初始化、登录和会话 |
| GET/POST/PATCH | `/api/users`、`/api/users/:id` | 管理员管理用户 |
| GET/POST | `/api/products` | 查询商品、管理员新增商品并记录期初库存 |
| GET | `/api/orders?search=&status=`、`/api/orders/:id` | 查询订单列表和详情 |
| POST | `/api/orders/demo` | 创建虚构待处理测试订单 |
| POST | `/api/orders/:id/confirm`、`/cancel`、`/ship`、`/complete` | 推进订单状态和库存 |
| GET | `/api/inventory/ledger` | 查询库存流水 |
| POST | `/api/inventory/adjustments` | 管理员登记有原因的库存正/负调整；阻止现有库存低于预占量 |
| GET/POST | `/api/backups` | 查询/创建本地备份 |
| GET | `/api/backups/status` | 查询异地备份是否配置 |
| POST | `/api/backups/retry-remote` | 管理员重试上传所有本地待同步快照 |
| GET | `/api/backups/remote` | 管理员列出 OSS 备份前缀中的远端快照 |
| GET | `/api/backups/:name/download` | 下载备份文件 |
| POST | `/api/backups/:name/restore` | 输入 `RESTORE` 后恢复快照 |
| POST | `/api/backups/remote/:name/restore` | 输入 `RESTORE` 后从 OSS 下载、校验并恢复远端快照 |

## 本地启动

```bash
npm install
npm run dev
```

历史本地运行方式为 Vite 地址，API 默认监听本机 `3001` 端口。当前 Next.js 新入口运行在 `3000`，完整兼容工作区通过 `/classic` 进入；数据文件在 `data/tradeflow.sqlite`，本地备份在 `data/backups/`。Next.js 迁移计划与 AI 安全边界见[Next.js 迁移与 AI 接入方案](NextJs迁移与AI接入方案.md)。

构建 Next.js 使用 `npm run build`；旧 Vue 静态兼容工作区使用 `npm run build:legacy`。容器部署指令和配置见 README；阿里云部署脚本会以 Compose `cloud` profile 启动 Next.js 与 Caddy HTTPS 入口。云端是否已部署应以阿里云控制台资源状态为准。

## 本地验证记录

在独立临时 SQLite 数据目录运行 API 验证，没有改动当前工作区数据库：

- 订单确认后按 SKU 预占库存；缺货订单仍为待处理状态并被拒绝确认。
- 管理员库存增加/减少需记录原因和操作者；只读角色调整被拒绝；低于预占量的库存调整被拒绝；新建商品会记录带操作人的期初库存。
- 取消待发货订单只释放该订单的预占；另一笔待发货订单的库存预占继续保留。
- 发货按订单数量扣减现有库存和预占库存；重复发货返回冲突；已发货订单可完成。
- 只读角色可以登录，但创建订单被服务端拒绝（403）。
- 手动快照成功；恢复必须明确输入 `RESTORE`；恢复前后做完整性检查，恢复成功后撤销会话，并恢复到快照时的数据状态。
- 使用隔离的本地 S3 兼容接口验证 OSS 备份对象精确上传、远端列表、云端快照恢复、恢复前安全副本、恢复后会话撤销，以及损坏数据库拒绝覆盖；这不是实际阿里云账号或 OSS 服务的验证。
- 使用隔离的本地 S3 兼容模拟器验证上传失败后本地快照保留、状态页显示待同步、管理员补传成功和远端对象可列出；模拟服务不代表实际阿里云 OSS 网络、授权和 ECS RAM 角色验证。
- 既有全栈阶段记录了当时的构建和 API 健康检查结果；Next.js 当前构建使用 `npm run build`。
- `npm test` 使用隔离临时 SQLite 数据目录和本地 S3 模拟器通过六项端到端 API 回归检查，覆盖管理员/运营/只读权限、商品初始库存流水、人工库存调整、取消释放、确认预占、完整预占校验后发货、重复发货拦截、完成订单、订单和用户权限审计、停用账号会话撤销、旧 SQLite 升级与旧结构快照恢复、OSS 上传失败后的手动补传，以及代理后的登录限流按访客 IP 隔离；另两项覆盖生产管理员初始化口令安全门。测试退出后会清理临时数据库，不修改开发数据。

生产首次管理员初始化门禁通过端到端 API 回归检查：正确口令创建成功，缺失或错误口令被拒绝，漏配口令会关闭初始化入口，创建后不能重复设置。

以上没有验证实际阿里云 OSS 上传、ECS RAM 角色取凭据、云资源部署或域名 HTTPS；这些需要目标账号、地域和资源后再完成。当前发货使用人工录入承运商和追踪号；平台订单同步、自动物流轨迹、面单采购与寄件创建不在当前项目范围内。
