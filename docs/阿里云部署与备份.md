# TradeFlow ERP 阿里云部署与备份

本文按当前项目结构说明如何将本地全栈应用部署到阿里云 ECS，并将数据库快照复制到 OSS。项目目前尚未连接任何阿里云账号；执行云资源购买、开放公网访问和绑定域名之前，应先确认地域、规格、预算和域名。

开始前先填写[阿里云上线参数表](阿里云上线参数表.md)，不要把云账号密钥或第三方 API Token 放进该表或聊天中。

## 部署结构

```text
用户浏览器 --HTTPS--> ECS Docker 网络中的 Caddy --> Next.js
                                                   |-- 同源 API 代理 --> Express --> SQLite --> 持久数据盘 /srv/tradeflow
                                                   |-- AI Route Handler --> AI 供应商（AI_API_KEY 仅在服务端）
                                                   `-- Express 定时/手动快照 --> 同地域 OSS Bucket
```

先用单台 ECS 运行 Docker Compose。云端 profile 启动 Next.js、Express API 和 Caddy；只有 80/443 暴露公网，Next.js 代理 `/api/*` 到 Express，Express 才能访问 SQLite。`.env` 的 `TRUST_PROXY_HOPS=1` 表示 Express 只信任来自 Next.js 容器的单跳转发；Next.js 仅传递 Caddy 所带的访客 IP 头。本地默认为 0。代理信任跳数必须与实际拓扑一致，避免客户端伪造代理头绕过 IP 判断，见[Express 官方代理配置说明](https://expressjs.com/en/guide/behind-proxies/)。AI 密钥通过服务端 `AI_API_KEY` 注入 `next-web`，严禁使用 `NEXT_PUBLIC_` 前缀。SQLite 数据和本地备份放在挂载后的持久数据盘中，OSS 保存异地快照。ECS 与 OSS 建议选同一地域，减少跨地域访问的不稳定性。官方地域端点列表：[OSS 地域和访问域名](https://help.aliyun.com/en/oss/user-guide/regions-and-endpoints)。

## 1. 准备阿里云资源

仓库中的 `infra/alibaba/` 提供可审阅的 Terraform 基础设施草案：创建 VPC/子网、安全组、按需 ECS SSH 入口、加密 ECS 系统盘和独立数据盘、私有加密 OSS Bucket，以及只允许访问指定备份前缀的 ECS RAM 角色。系统盘和数据盘默认每日 03:00 自动快照并保留 7 天；OSS 生命周期规则默认仅对备份前缀设置 365 天过期，`backup_retention_days` 可在 30 到 3650 天间调整，不会匹配其他前缀对象。Terraform **不会**安装应用、格式化或挂载数据盘、购买/备案域名或写入 DNS；应用 Compose 配置包含 Caddy，域名 DNS 指向 ECS 且开放 80/443 后会自动申请和续期 TLS。配置示例见 `infra/alibaba/terraform.tfvars.example`。

在工作副本中执行前：安装 Terraform 1.6 或更新版本；将示例复制为未纳入版本控制的 `terraform.tfvars`，填入阿里云控制台确认可用的可用区、ECS 规格、Alibaba Cloud Linux 3 镜像 ID、已有 ECS 密钥对和全球唯一 Bucket 名称。通过阿里云 CLI 配置或 Terraform 支持的临时凭据方式认证，不要把 AccessKey 写进 Terraform 文件、变量文件或聊天。运行 `terraform init`、`terraform fmt -check`、`terraform validate` 和 `terraform plan -out=tradeflow.tfplan`，查看 `terraform show tradeflow.tfplan`，并在阿里云价格计算器核对 ECS、云盘、公网流量和 OSS 账单；只有计划和费用均确认后才手动执行 `terraform apply tradeflow.tfplan`。不要自动化跳过 plan 审阅。

Terraform state、`.tfplan` 和 `terraform.tfvars` 已加入 `.gitignore`。把 state 保存在受限且加密的安全位置；此草案没有配置远程 state 锁。OSS Bucket 和 ECS 数据盘含 `prevent_destroy` 保护，避免一次 `terraform destroy` 连同数据库备份或数据盘一起误删。即使删掉 Terraform 状态，阿里云 ACL 资源也不会由 Provider 自动恢复或删除；销毁资源前先确认数据盘和 OSS 备份的保留计划。

资源字段参考阿里云官方 Provider 的 [ECS 实例](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/instance.html)、[ECS 数据盘](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/ecs_disk)、[OSS Bucket](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/oss_bucket.html)、[RAM 角色策略绑定](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/ram_role_policy_attachment.html)和[ECS 实例 RAM 角色绑定](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/ecs_ram_role_attachment.html)文档。Provider 和阿里云服务会更新；执行前要按选定地域、实例规格复核 `plan`。

如不使用 Terraform、改为在控制台手工创建资源，请按以下顺序操作：

1. 选定 ECS 和 OSS Bucket 的同一地域。杭州示例地域 ID 为 `cn-hangzhou`；如果选其他地域，使用该地域对应的 OSS Endpoint。
2. 创建一台 Alibaba Cloud Linux 3 ECS。CPU、内存和系统盘规格根据用户数、并发和预算选定；本项目当前是小型 SQLite 应用，部署前需要结合预期流量核算，不在这里代替账户下单。
3. 为 ECS 配置独立数据盘，挂载到 `/srv/tradeflow`。首次挂载新盘前先确认盘内没有需要保留的数据，再按阿里云文档完成分区、文件系统和开机自动挂载：[创建并使用数据盘](https://help.aliyun.com/zh/ecs/user-guide/create-and-use-a-data-disk)。
4. 创建 OSS 私有 Bucket，禁止公共读写。只把备份放在独立前缀（默认 `tradeflow/`）。Terraform 默认令该前缀下快照在 365 天后过期，可通过 `backup_retention_days` 调整；生命周期到期删除不可恢复，应用本地仅保留最新 30 份。恢复要求更长时，应在 plan 阶段核对保留天数和费用。参考[OSS 生命周期规则](https://help.aliyun.com/zh/oss/user-guide/configuration-examples)。
5. Terraform 将默认创建每日自动快照策略并附加到 ECS 系统盘和独立数据盘；每天凌晨 03:00（UTC+8）生成快照，保留 7 天，`ecs_snapshot_retention_days` 可调整为 1 到 365 天。云盘快照会增加存储费用，apply 前按实际磁盘占用与增量快照规则估价；仍需保留 OSS 数据库快照作为独立恢复路径。参考[阿里云 ECS 自动快照策略](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/ecs_auto_snapshot_policy)和[自动快照策略附加](https://registry.terraform.io/providers/aliyun/alicloud/latest/docs/resources/ecs_auto_snapshot_policy_attachment)。
5. 为 ECS 绑定仅能列举、读取和写入指定 Bucket/前缀对象的 RAM 角色。应用支持从 OSS 列出并直接恢复快照，因此需要 `oss:ListObjects`（用 `oss:Prefix` 限制备份前缀）、`oss:GetObject` 和 `oss:PutObject`；不要授予删除对象或公共访问权限。优先使用实例 RAM 角色和临时凭据，避免长期 AccessKey。参考[RAM 策略按目录授权](https://help.aliyun.com/en/oss/user-guide/access-control-base-on-ram-policy)。

## 2. 安装 Docker 并部署

阿里云官方提供 Alibaba Cloud Linux 3 的 Docker 和 Compose 安装流程：[在 Linux ECS 安装 Docker 和 Compose](https://help.aliyun.com/zh/ecs/user-guide/install-and-use-docker)。仓库中的 `infra/alibaba/deploy-ecs.sh` 按该流程安装 Docker CE 和 Compose 插件，并检查 `.env`、真实域名、数据盘挂载和目录权限后构建、启动应用与 Caddy。脚本只支持 Alibaba Cloud Linux 3，不会格式化或挂载数据盘、购买/备案域名或修改 DNS。

当前本地项目目录没有 Git 远程仓库。部署源码前需先推送到私有 Git 仓库，或通过安全文件传输复制项目源码；不要上传 `data/`、`node_modules/`、`.env`、Terraform state/plan 或密钥文件。到 ECS 后在项目根目录创建生产 `.env`，将 `TRADEFLOW_DOMAIN` 改为已经解析到 ECS 公网 IP 的真实域名，并完成数据盘挂载，再执行：

```bash
sudo bash infra/alibaba/deploy-ecs.sh
```

脚本只在 `/srv/tradeflow` 已确认为单独挂载点时继续；空目录会设为容器 UID 1000 所有，其它现有数据和所有权若不匹配会停止，不会自动改写。启动后检查脚本输出、Caddy 配置和后端健康状态；确认 DNS 与 80/443 可达后，从公网浏览器验证 HTTPS。

若手工逐步安装，可参考：

```bash
git clone <项目仓库地址> /opt/tradeflow
cd /opt/tradeflow
```

上面 `git clone` 仅适用于已经推送到私有 Git 仓库的情况。数据盘挂载后不要对 `/srv/tradeflow` 执行递归 `chown`；新空目录应由部署脚本设置容器 UID 权限，已有数据库文件需逐项确认后再迁移权限。

在项目目录放置 `.env`，至少配置 OSS 参数（密钥不应提交到仓库或聊天中）：

```dotenv
BACKUP_S3_BUCKET=你的私有Bucket名称
TRADEFLOW_DOMAIN=erp.你的域名
TRUST_PROXY_HOPS=1
TRADEFLOW_DATA_DIR=/srv/tradeflow
TRADEFLOW_SETUP_TOKEN=请替换为至少32位的随机初始化口令
BACKUP_S3_REGION=cn-hangzhou
BACKUP_S3_ENDPOINT=https://s3.oss-cn-hangzhou.aliyuncs.com
BACKUP_S3_FORCE_PATH_STYLE=false
BACKUP_S3_PREFIX=tradeflow
BACKUP_S3_CREDENTIAL_MODE=ecs_ram_role
BACKUP_S3_RAM_ROLE_NAME=你的ECS实例RAM角色名称
# 可选：Next.js 服务端 AI 助手；密钥只放在此服务器端 .env
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=你的服务可用模型名
AI_API_KEY=服务器端密钥
```

AI 助手尚未配置模型时，Next.js 和 ERP 仍能启动；助手接口会提示管理员配置 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。`AI_API_KEY` 不得添加 `NEXT_PUBLIC_` 前缀或提交到 Git。

将 RAM 角色绑定到 ECS，并授予它对专用 Bucket/前缀列出、读取和写入对象所需的最小权限。阿里云 Credentials SDK 会从 ECS 元数据服务取得并自动刷新临时凭据；应用通过 `BACKUP_S3_CREDENTIAL_MODE=ecs_ram_role` 启用这一认证方式，不需要在 `.env` 填长期 AccessKey。AWS SDK v3 通过 S3 兼容接口访问 OSS，应用明确使用文件长度并关闭非必要的请求校验流式包装，以兼容 OSS 的上传传输要求。参考[阿里云 AWS SDK 接入 OSS](https://help.aliyun.com/en/oss/developer-reference/use-aws-sdks-to-access-oss)和[ECS 实例 RAM 角色](https://help.aliyun.com/en/ecs/user-guide/attach-an-instance-ram-role-to-an-ecs-instance)。如果不是运行在 ECS 上，可使用受限的 RAM 用户临时凭据并按计划轮换。

首次打开 HTTPS 站点时，创建管理员页面还会要求“部署初始化口令”。在 ECS 上使用 `openssl rand -base64 48` 生成随机值，写入 `.env` 的 `TRADEFLOW_SETUP_TOKEN`（至少 32 个字符）并妥善保管。部署脚本会拒绝空口令或过短口令；首个管理员创建后，初始化接口自动关闭。不要将该口令写入 Terraform、镜像、代码或聊天记录。

设置 `TRADEFLOW_DATA_DIR=/srv/tradeflow` 后，Compose 会将宿主机目录绑定到容器 `/data`，确保 SQLite 和本地备份落在已挂载的数据盘。`.env.example` 的默认值 `tradeflow-data` 适合本机 Docker 命名卷。

Terraform 输出会给出 `data_disk_id`。首次部署时，在 ECS 内用 `lsblk -f` 对照控制台和 Terraform 输出确认新建的空白盘设备，再按阿里云文档格式化、挂载到 `/srv/tradeflow` 并配置开机自动挂载；不要仅凭设备名猜测后直接格式化。部署参数使用 Terraform 输出的 OSS Bucket、地域、RAM 角色名和 `tradeflow` 前缀填入 `.env`。

如果没有使用 `infra/alibaba/deploy-ecs.sh`，手动启动并查看服务：

```bash
docker compose --profile cloud up -d --build
docker compose ps
docker compose logs --tail=100 tradeflow
docker compose logs --tail=100 caddy
curl http://127.0.0.1:3001/api/health
```

新建 ECS 数据目录时，生产默认创建空业务数据库，不会灌入虚构商品或演示订单。首次打开站点后创建管理员账户并录入真实商品/库存。只有专用演示部署才在 `.env` 显式设置 `TRADEFLOW_SEED_DEMO_DATA=true`。如需迁移已有演示数据，先在旧环境生成并下载备份，在新环境恢复，再核对订单、库存和用户。

## 3. 配置 HTTPS 入口

- 将域名 A 记录指向 ECS 公网 IP，并按适用要求完成域名备案。
- ECS 安全组只开放需要的入站端口：SSH 限制为管理员来源地址，HTTP 仅用于证书签发/跳转，HTTPS 对业务用户开放。不要开放应用的 3001 端口。
- Compose 云端 profile 会运行 Next.js、Express 和 Caddy。Caddy 反向代理到 Next.js 并自动申请/续期公网 TLS 证书；证书签发要求真实域名 DNS 指向 ECS，公网能访问 80/443，且 `caddy_data` 卷保持持久。Caddy 的自动 HTTPS 与公网可达要求见[官方说明](https://caddyserver.com/docs/automatic-https)和[反向代理快速入门](https://caddyserver.com/docs/quick-starts/reverse-proxy)。
- 登录后验证订单、库存和权限页面；从“备份管理”创建快照并确认异地状态成功。

## 4. 备份与恢复

应用首次启动会生成一份启动快照，此后每 24 小时创建本地自动备份；本机保留最近 30 份。管理员可以手动创建、下载或恢复。配置 OSS 后，新创建的本地快照会同步到 `BACKUP_S3_PREFIX/`，页面显示上传状态。失败时本地副本仍保留。

备份管理页还会列出 OSS 前缀中的云端快照。管理员选择“下载并恢复”后，服务端从 OSS 下载到临时文件，校验 SQLite 完整性和必要应用表，再把当前数据库保存为恢复前安全副本，最后替换数据库并撤销所有登录会话。无效快照不会覆盖当前数据。ECS 与数据盘同时损坏时，在新 ECS 部署应用、配置同一 Bucket/前缀及 RAM 角色后，可从此列表恢复，无需先手动把文件放入本机备份目录。

上线前至少做一次恢复演练：在隔离的测试环境配置同一 Bucket/前缀，使用“OSS 云端备份”恢复，再确认订单、库存流水和用户数据一致后制定正式恢复流程。不要直接在生产库上用演练恢复覆盖业务数据。另为 ECS 系统盘/数据盘设置定期云盘快照；云盘快照与 OSS 数据库备份提供不同恢复路径。[阿里云 ECS 云盘快照](https://help.aliyun.com/zh/ecs/user-guide/create-a-snapshot)。

## 5. 上线检查表

- [ ] ECS 与 OSS 地域已定，规格和月度预算已核对。
- [ ] 数据盘已挂载到 `/srv/tradeflow`，重启 ECS 后挂载仍有效。
- [ ] OSS Bucket 为私有，RAM 权限限定到目标 Bucket/前缀。
- [ ] `.env` 未纳入 Git，密钥不出现在日志和前端。
- [ ] HTTPS 正常，3001 端口未对公网开放，SSH 来源受限。
- [ ] 首次管理员账户已创建，已新增至少一个非管理员账户并核对权限。
- [ ] 新建备份显示 OSS 上传成功，下载和测试环境恢复已验证。
- [ ] ECS 云盘快照和 OSS 生命周期规则已确认。
- [ ] 设置 ECS 磁盘/内存/CPU 监控、应用健康检查和异常通知。
