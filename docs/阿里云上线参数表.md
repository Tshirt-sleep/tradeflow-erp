# 阿里云上线参数表

云端部署包、SQLite 持久化和 OSS 备份代码已经准备好；目前还没有在任何阿里云账号创建资源。开始开通 ECS、OSS 等可能计费的资源前，先确认下面的部署参数。账号密钥和 API Token 不要填写在此文档或发到聊天中。

## 需要确认

| 项目 | 请填写/选择 | 建议 |
|---|---|---|
| 阿里云账号 | 已有 / 尚未注册 | 需要能创建 ECS、VPC、RAM 和 OSS 的权限 |
| 部署地域 | `cn-hangzhou` / 其他： | 选择与你和团队较近的大陆地域；ECS 与 OSS 放同一地域 |
| 域名 | 已有： / 暂无 | 已有域名填写计划使用的主机名；HTTPS 入口用 443，应用端口 3001 不对公网开放 |
| 每月预算上限 | ¥： / 暂未确定 | 先按 ECS、系统盘/数据盘、公网流量、OSS 和快照合计核算，再创建资源 |
| SSH 管理来源公网 IP | 暂不确定 / `x.x.x.x/32` | 安全组只允许这个来源登录 SSH，不开放给全网 |
| OSS 快照保留天数 | 默认 365 天 / 其他： | Terraform 生命周期规则仅作用于 `tradeflow/` 备份前缀，过期后不可恢复 |
| ECS 自动快照保留天数 | 默认 7 天 / 其他： | 默认每日 03:00（UTC+8）备份系统盘和数据盘；费用在 apply 前核算 |
| 初始部署方式 | 空白环境 / 迁移现有演示数据 | 迁移时先下载 SQLite 备份，再在云端恢复并核对数据 |

## 不要发送到聊天的资料

- 阿里云 AccessKey ID/Secret、控制台密码、MFA 验证码。
- SQLite 数据库或包含买家信息的文件。

这些凭据应在服务器的 `.env`、受控密钥服务或 ECS RAM 角色中配置。阿里云 ECS 建议使用实例 RAM 角色访问 OSS，不为应用保存长期 AccessKey。

## 参数确认后执行的顺序

1. 按地域、规格与预算确认 ECS、数据盘和私有 OSS Bucket。
2. 限制 ECS 安全组：SSH 仅允许管理 IP，HTTPS 对业务用户开放，不开放 3001。
3. 绑定最小权限的 ECS RAM 角色，只允许访问应用备份前缀。
4. 在 ECS 安装 Docker，部署 TradeFlow，配置域名 HTTPS。
5. 创建管理员、验证订单与权限，创建 OSS 快照并在隔离环境演练恢复。
6. 云端健康检查和备份验证通过。

云端创建、绑定域名以及资源账单尚未验证；完成前不要将公网服务视为生产可用。
